# SPIF v1 传输与记录契约

协议已连接 FPGA 采集/处理核心、FX2 Slave FIFO 和在线上位机。当前控制版增加了显式采集启停；连接 USB 只建立“已准备、已停止”状态，不会自动启动 CCD。此协议是本项目定义的协议，不假定与开发板原厂固件兼容。

## 包头与校验

所有整数为小端。固定 36 字节包头，随后为指定长度的 payload，最后 4 字节 CRC-32/ISO-HDLC（小端）。CRC 覆盖整个包头和 payload，不包含 CRC 自身：反射多项式 0xEDB88320，初值和最终异或值均为 0xFFFFFFFF；校验向量 ASCII `123456789` 为 0xCBF43926。

| 字节偏移 | 字段 | 格式/含义 |
|---|---|---|
| 0 | magic | ASCII SPIF，4 字节 |
| 4 | version | u8，固定 1 |
| 5 | kind | u8，见下表 |
| 6 | flags | u16，位 0 无效结果，位 1 数据不连续，位 2 时间戳有效；其他位必须为 0 |
| 8 | payload_length | u32，必须与 kind 的固定长度相符 |
| 12 | sequence | u32，每个方向独立、全包类型共用、逐包加一；允许回绕 |
| 16 | frame_id | u32，对应采集帧；配置和 ACK 使用 0xFFFFFFFF |
| 20 | timestamp | u64，采集首个有效像素时的 100 MHz 计数；时间戳无效时必须为 0 |
| 28 | source_version | u32，与 RTL 的 S 版本完整一致，不截成 16 位 |
| 32 | k_version | u32，与 RTL 的 K 版本完整一致 |

RAW、SPECTRUM、PHASE 和 RESULT 的有效时间戳来自 FPGA 100 MHz 自由运行计数器。原始帧未绑定处理标定时版本填写 0；经过处理的帧携带实际使用的版本。设备复位/重连须开始新的记录会话和序号跟踪器，不能把复位当作自然回绕。

## Payload

| kind | 方向 | 长度 | 字节布局 |
|---|---|---|---|
| 0x10 RAW | FPGA→主机 | 2048 | 1024 个 u16 ADC 值，只允许 0..4095，已取中间像素 |
| 0x11 SPECTRUM | FPGA→主机 | 10240 | 每点依次 S0:u16、S1:u32、S2:i32，共 1024 点；S1 为无符号 24 位 Q12，S2 为符号扩展的 25 位 Q12 |
| 0x12 PHASE | FPGA→主机 | 8192 | 1024 个 i64，分别为符号扩展的 43 位 P1，π=2³¹；本包不包含 P0 |
| 0x13 RESULT | FPGA→主机 | 28 | 有符号 84 位累加值符号扩展成 96 位，占 12 字节；随后 exponent:i16、peak:u16、left:u16、right:u16、dropped_frames:u32、malformed_frames:u32 |
| 0x20 SOURCE | 主机→FPGA | 4096 | 1024 个 u32 的 S 倒数 Q30，范围 1..2³⁰ |
| 0x21 K_WEIGHTS | 主机→FPGA | 2052 | exponent:i16、保留 u16=0，随后 512 个 i32 权重，整数和必须严格为零 |
| 0x22 ACK | FPGA→主机 | 8 | 对应命令 sequence:u32、status:u16、保留 u16=0 |
| 0x23 EXPORT_CONTROL | 主机→FPGA | 4 | RAW/S0 输出间隔 u32；0=关闭，1=每帧，N=每 N 帧 |
| 0x24 ACQUISITION | 主机→FPGA | 8 | W:u32、T:u32；W=0..1024，T=2114..5000 个 5 MHz 像素周期 |
| 0x25 RUN_CONTROL | 主机→FPGA | 4 | u32；0=安全停止，1=开始，其他值非法 |

RESULT 的距离为 signed_accumulator×2^(−exponent)，单位由保存的 K 和距离比例定义。累加值在 Python 中使用任意精度整数，在 CSV 中保存十进制整数字符串，不先转换为 double。无效标志有效时，主机将距离视为 NaN，CSV 留空，不能把零显示成一次有效测距。主峰范围使用 1..511，left≤peak≤right；没有主峰时允许三者均为 0，并应携带无效标志。

P1 以整帧方式发送时，帧内任一点无效应合并到包头无效标志。发包集成需要完整帧缓存或等效的元数据提前确认，不能在已经发送包头后才发现需要修改该标志。

ACK status 定义：0=命令已完成，1=非法 payload/参数，2=配置忙，3=硬件配置校验失败，4=核心故障。0 **不是仅收到命令**。RUN_CONTROL=0 会先禁止新帧，在当前帧、Ping-Pong、算法及发包通路全部排空后才返回 ACK；RUN_CONTROL=1 使能采集并返回 ACK，随后约 100 ms 的模拟稳定期帧不会发布。开始/停止不清除 W/T、S/K、版本号或 USB 包序号；W/T 重配置仍会按原规则使 S/K 失效。FPGA 收包器先缓存完整命令并检查 CRC、长度和取值，再开始事务。超时不能假定命令未生效，也不能盲目重发会增加版本的配置命令。

## 吞吐与背压

以当前最快 422.8 μs 帧周期估算，全帧 RAW+RESULT 含包开销约 5.1 MB/s；再每帧增加 SPECTRUM 后总量约 29.4 MB/s。虽未超过 USB 2.0 理论线速，但持续可用带宽还受FX2、主机调度和协议开销限制，不能配置所有中间量全帧导出后仍声称任意主机上无损实时。

默认集成方向为 RAW 和 RESULT 每帧输出，中间光谱/相位可选抽帧诊断，图形显示按较低刷新率取最新帧。保存需要的通道由接收工作线程完整记录，显示抽帧不应导致记录抽帧。若需要每帧保存所有阶段，必须明确降低 CCD 帧率或采用更高带宽链路。持续输出阻塞会耗尽双缓冲并导致整帧丢弃，计数必须暴露给用户。

`packet_tx.v` 接受一次包命令，锁存元数据，输出包头，再握手接收恰好 payload_length 个字节，最后输出 CRC；m_last 只标记最后一个 CRC 字节。不缓存完整 payload，不执行 payload 数值检查，不负责端点或 USB 时序。任意 m_ready 背压下输出保持，s_valid 断续不会改变 CRC。非法 kind/长度/保留标志/时间戳组合会拒绝命令并产生 cmd_error。少送 payload 会停等，集成层负责超时和复位恢复。

## 主机保存与回放

`host/protocol.py` 使用有界缓冲按字节流重组，CRC/语义错误包不交给显示；序号跟踪单独报告缺包、重复和倒序，不按 frame_id 推断包顺序，因为采集与解算会重叠。CRC 检测偶发传输损坏，不是身份认证机制。

`host/recording.py` 的 Recorder 先保存每次收到的原始字节（包括坏包）到 stream.spif，再解码并写 distance.csv。manifest.json 保存用户元数据、接收/解析计数、缺包及无效结果计数；独占新建会话目录，拒绝覆盖已有记录。周期性 flush 可以将缓冲落盘，异常中断/USB 断开/断尾不会标为干净结束；正常关闭但存在 CRC 或缺包时 transport_integrity_ok 仍为 false。该标记只描述记录传输完整性，不证明 CCD 有效窗口、光学准确度或设备从未丢弃输入帧；设备的两个计数另存于每个距离记录。

Recorder 应由单个接收工作线程调用；文件错误直接向上抛出，调用方须停止记录并通知用户。on_packet 只应用于更新最新帧/队列，不应在接收线程同步绘图。S/K 标定文件与版本对应关系仍需 GUI/配置管理器记录，目前 Recorder 不会虚构或自动推断这些内容。

命令行可用 `python host/recording.py saved_session/stream.spif` 校验回放并打印距离。回放直到文件结束才给出完整性结论，不能把中间成功解出的若干包当作全文件无损证明。GUI 在线连接时自动发送一次 STOP，以建立确定状态；开始、停止和正常断开都等待匹配 ACK。离线回放默认按 100 MHz 时间戳 1× 调度，支持 0.25×、0.5×、1×、2×、4×和不限速，并可在播放中切换。旧记录缺少有效时间戳时，优先使用 manifest 的 T 和 frame_id 估算，否则按 422.8 μs，并明确显示“估算节奏”。

## 已验证证据

`sim/test_protocol.py` 覆盖全部支持的包类型、独立逐位CRC参考、正负84位极值、逐字节及多种分片边界、噪声重同步、非法长度和CRC/数值错误、断尾、标定系数及序号回绕。`scripts/test_packet.ps1` 同时运行该测试和Vivado RTL仿真，覆盖payload间断、输出背压、中途复位与非法命令拒绝；RUN_CONTROL另由`test_run_control.ps1`覆盖。

`sim/test_recording.py` 通过 4 项测试：字节原样保存及回放、距离整数精度和无效值、拒绝覆盖、异常/断尾记录状态、CRC 错误与缺包保留证据且不认证完整性，以及设备主动标记的不连续。尚未做实际 USB 持续带宽、磁盘写满或长时间实测。
