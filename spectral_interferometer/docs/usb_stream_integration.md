## 输出分叉与整包锁定的依赖风险（待动态确认）

代码审查发现潜在循环等待：acquisition_core 的 RAW/处理分叉需要两路都消费当前像素才能推进；spectral_processor 的 input_open 要等当前距离结果被接受才重新打开。若调度器先锁定下一帧 RAW 包，RAW 发包器可能只能消费首点，之后等待处理支路 ready；上一帧 SPECTRUM 又需要同一调度器授权才能排出、推进 FFT/结果。仅验证帧缓存中有完整输入帧，不等于经过分叉后的完整 RAW 输出不依赖其他发包通道。

此为基于当前 RTL 的依赖分析，四路仿真仍运行中，尚无动态失败结论。若确认，需完整帧输出缓冲或等效消除依赖的结构，不能靠调度器任意中断半包解决。另已询问用户高速模式下各光谱流的逐帧保存要求；未擅自选择抽帧策略。

## 2026-09-20：字节与 16 位字适配

`rtl/usb_word_stream.v` 提供同一时钟域内的 ready/valid 适配。发送方向将先到字节放入 word[7:0]、后到字节放入 word[15:8]，包尾标记随最后一个完整字传递；接收方向按相反过程还原字节。两端均在下游暂停时保持有效数据及包尾标记，复位清除未完成字。

### 同日补充：实际传输桥连接

`rtl/usb_stream_bridge.v` 将现有模块连接为 TX 字节打包→跨时钟字 FIFO，以及 RX 跨时钟字 FIFO→字节拆分两条路径。复位同时清除对应字节适配器和 FIFO，RX 字节输出侧采用本时钟域同步释放的复位。各桥的 rst 输入仍必须同步于其写时钟；生产顶层需要分别生成系统域及 IFCLK 域复位，不能把两个独立时钟域当成同步域使用。

`test_usb_async_fifo.ps1 -Bridge` 在完成上述 FIFO 回归后，连接 TX 100 MHz→约 48 MHz，再由 RX 返回 100 MHz，共验证 100 个 68 字节测试包、6800 字节，逐字节及包尾核对并检查背压下输出保持，最终排空无多余字节。使用真实 XPM 模型；日志 `build/usb_async_sim/bridge_xsim.log` 已 PASS。这是数据通路回环，不包含 packet_tx 的 CRC、真实 FX2 引脚或 USB 主机。RX 的 s_last 只是可选传输边界元数据；实际配置解析必须依据 SPIF 长度/CRC，不能将它视为 SPIF 命令结束。

SPIF 包尾与 USB 传输边界不是同一概念；接收解析不得依赖 USB 一次读取恰好对应一个 SPIF 包。当前模块的 m_last 只携带上游边界，不自行生成 PKTEND，也不假定 USB OUT 的包边界就是配置命令边界。实际字节映射、吞吐、时序和端点行为仍需在完整控制器及真实 J5 链路上核验。

本轮没有更新 FPGA 位流、没有发送 USB bulk 数据、没有修改 FX2 固件；原始 Vivado 工程中的用户改动保持不动。
